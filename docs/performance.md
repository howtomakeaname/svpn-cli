# 真实链路性能记录

2026-11-13，在 Linux amd64 开发机上用 Go 1.27.4 构建，经过真实 VPN 网关访问授权的 Ubuntu 主机。以下数据对应提交 `01b43c8` 的 v0.2.0 功能集；不代表后续 UDP、TUN 或 TLCP 版本的性能。新增传输能力的范围见 [传输能力](transports.md)。它是特定链路和时间段的观测，不是网关带宽上限或所有部署的性能承诺。主机地址、组织策略、认证信息和私钥不随记录发布。

## 测量方式

- 在授权主机的获准且空闲端口运行临时 Go HTTP/HTTPS 流式服务，用随机令牌验证请求；不修改现有服务或网络策略。
- 对照组直接调用同一份 Go VPN 连接引擎，不经过本地代理。它仍包含 VPN 网关与取票开销，并非裸公网连接。
- 比较普通 HTTP 代理的 `vpn-only` / `auto`、SOCKS5、HTTPS CONNECT、本地端口转发和 VPN + SSH 反向转发。`auto` 测的是命中 VPN 资源的路径。
- 反向转发由授权主机发起请求，经远程回环监听、VPN + SSH 隧道访问开发机上的临时服务；反向模式的上下行以该请求客户端为参照，不能直接当作相同物理方向的普通转发结果。
- 小请求先记录该模式的首次请求，再测 20 次独立连接与 20 次应用连接复用的 p50/p95。首次请求可能包含取票与 TLS 建连，进程初始化单独记录；不清空服务端或共享引擎缓存，因此首次请求不代表所有缓存都冷启动。
- 传输负载为每批总计 8 MiB，在 1 / 4 / 16 个并发连接间均分；分别测试下载和上传，传输批次使用新连接。上传由服务端确认字节数，下载由客户端核验字节数；一批内全部连接成功才计算该批吞吐。
- 首轮每项测三批，随后补充五轮、每项每轮一批，通常合计八个有效样本。补充轮每轮将模式顺序循环移动两个位置，不重复小请求延迟测试。所有模式顺序测试，没有同时争抢链路的多模式测试。
- 吞吐均值为成功批次速度的算术平均，标准差使用样本标准差（分母 `n−1`），同时保留中位数、有效组数及观察到的失败组数。失败不算作零速度，也不从记录中抹去。汇总 CSV 另提供总字节数除以总耗时的聚合速度，它与批次速度的算术平均不同。
- CPU 记录 CLI 进程在各测量区间使用的用户态与内核态时间，总 CPU 时间除以总墙钟时间，按单核占比表示；内存为各 CLI 进程 RSS 高水位的最大值。基准调用进程和目标服务不计入 CLI 占用；没有 CLI 进程的对照组记为 N/A。
- 首轮首尾各测一次相同 HTTP 对照（表中 A/B），补充轮继续保留两个对照位置并轮换顺序。HTTPS 服务的临时证书通过已校验的 SSH 会话传递并显式信任，未关闭证书验证。

## 结果

成功批次共 **429** 个，核验有效载荷 **3,432 MiB（约 3.35 GiB）**；另外观察到 **1** 个失败批次。多数单元格 `n=8`，HTTP 对照 B 的 16 并发上传 `n=5`。

## 解释与边界

普通 HTTP 代理设置上游不复用连接，因此应用复用到本地代理的连接，并不能消除每次上游 TLS/CONNECT 的开销。SOCKS5、固定端口转发和 HTTPS CONNECT 会透传一个持续 TCP 流，应用可在其中复用连接。对于频繁的小请求，这个区别比单次大块传输的拷贝开销更明显。

本次对照 A 的单连接下载也有明显波动，均值 7.54 MiB/s、样本标准差 2.77 MiB/s。并发连接可能分摊建连延迟，也可能受到链路拥塞、丢包或网关限制影响；本次未确定波动的具体来源。顺序实测不能把不同模式间的全部差值归因于 CLI；小于首尾对照波动的差异尤其如此。短批次测量包含 TCP 启动和连接建立开销，不等于长时间单流的极限带宽。

资源策略之外的测试端口被拒绝，CLI 未回退直连。获准端口也可能因网关或目标网络原因无法建立隧道；本次只在实际可达的获准端口进行数据测量。失败的准备尝试不计入吞吐结果。

反向转发使用专用测试密钥、严格校验已有服务器主机密钥，不使用个人默认私钥。已核验五轮测试的 10 次转发监听在退出后关闭、远端临时公钥授权移除、测试进程退出及临时目录删除；本地临时密码文件也已删除。专用本地密钥保存在被版本控制忽略的私密目录中。当前不提供自动重连，活动隧道仍受资源票据有效期限制。

本次没有单独测量 `connect` 的标准输入输出拷贝、`auto` 未命中资源时的直连分支、超过 16 并发的负载，或持续到票据到期的长时间传输。Windows/macOS 的真实网关性能也尚未测量。
