# v0.3 传输实测记录

记录日期为 2026-11-13 UTC（北京时间 11 月 13–14 日）。Linux amd64，Go 1.27.4，CGO 关闭；真机吞吐使用 `dd43076` 构建的 `v0.3.0-dev`，后续改动为能力元数据、测试与文档。没有使用官方客户端作为运行依赖。

## 真机 TCP 与 TUN 吞吐

同一开发机经真实 VPN 网关访问授权 Linux 主机上的临时 HTTP/HTTPS 流式服务。服务使用随机请求令牌，HTTPS 临时证书经校验过的 SSH 会话传递并显式信任。每批合计 8 MiB，均分到 1/4/16 个连接，分别上传和下载；每轮每项一批，共五轮，模式顺序每轮循环移动两位。传输使用新连接，核验完整下载及服务端上传字节数，不把失败算成零速度。

**300 批全部成功，已核验 2,400 MiB（约 2.34 GiB）载荷。** 各单元格有效数均为 `n=5`。单元格为 **算术均值 ± 样本标准差（中位数）**，单位 MiB/s；统计描述这些顺序观测，不作统计显著性或带宽上限保证。

TUN 的请求程序在真实 Linux 网络命名空间中运行，通过内核 TUN 进入宿主网络中的 CLI；不是绕过虚拟网卡直接调用 Go 拨号器。HTTP 对照 A/B 直接调用同一 VPN 引擎，仍包含网关开销。`auto` 测的是匹配 VPN 资源的分支。

### CLI 资源占用

CPU 为五轮总用户态/内核态 CPU 时间除以总测量墙钟时间，按一个 CPU 核心表示；RSS 为五个 CLI 进程的最高高水位。没有单独 CLI 进程的对照记为 N/A。启动时间是五次进程初始化的中位数。

| 模式 | 单核 CPU | 峰值 RSS MiB | 启动秒 |
| --- | ---: | ---: | ---: |
| HTTP 对照 A | N/A | N/A | N/A |

这些区间包含建连和等待，CPU 不是瞬时峰值，也不包括测量客户端、目标服务及系统网络缓冲。本轮不重复 v0.2 的 20 次小请求延迟流程，因此不能直接比较两个版本的区间平均 CPU。

网络波动很大：例如 HTTP 对照 A 的 4 并发下载为 7.35 ± 4.31 MiB/s。没有剔除低速样本，也未确定波动来源。顺序模式之间的全部差值不能归因于 CLI 或 TUN；每批只有 8 MiB，结果包含建连及 TCP 启动开销，不等于持续单流吞吐上限。

## 真实 UDP DNS 往返

测试使用策略明确允许的 DNS 目标，查询公开域名并校验响应 ID、响应标志和 RCODE=0。原生引擎、SOCKS5 UDP、真实 TUN 各五轮，每轮 30 次，共 **450 次均成功**；另保留首轮功能验收的 60 条数据，单独标为 `acceptance`，不混入五轮统计。

各轮首个请求单列，原生入口将建立 UDP 隧道的时间计入首请求。各轮后 29 次形成一个温连接均值；表中 ± 为这 **5 个组均值**的样本标准差，中位数/p95 来自各模式的 145 次温连接请求。模式按顺序测量，票据/进程缓存不同，不能据此精确估算本地入口的净延迟开销。

| 入口 | 温连接均值 ± 组均值 SD ms | 温连接中位数 ms | 温连接 p95 ms | 首请求均值 ms |
| --- | ---: | ---: | ---: | ---: |
| 原生 VPN 引擎 | 66.01 ± 4.59 | 63.08 | 80.34 | 355.69 |
| SOCKS5 UDP | 75.65 ± 10.41 | 65.11 | 101.00 | 359.81 |
| 真实 Linux TUN | 68.58 ± 3.98 | 64.85 | 91.94 | 393.15 |

本部署的可验证 UDP 资源仅为 DNS，未向其他端口发送 UDP 吞吐负载。本表验证小数据报的真实往返，不代表 QUIC、游戏、音视频或大报文 UDP 吞吐已实测。

## 本地独立 TLCP 互操作

GmSSL 3.2.0 作为独立 C 实现，在回环地址提供测试 CONNECT/回显服务；实际 CLI 经 `forward --session` 接入，使用临时 SM2 CA 与签名/加密双证书。GCM、CBC 各五批，每方向 8 MiB，同时发送和接收，校验字节数及 SHA-256；**10 批全部成功**。这里没有真实组织的网关或登录票据，不能替代国密部署的真实联调。

| 套件 | 每方向吞吐均值 ± 样本 SD MiB/s | 中位数 MiB/s | 有效批次 |
| --- | ---: | ---: | ---: |
| ECC_SM4_GCM_SM3 | 19.00 ± 0.83 | 18.64 | 5 |
| ECC_SM4_CBC_SM3 | 35.57 ± 0.20 | 35.63 | 5 |

吞吐按 8 MiB / 整个双向回显耗时计算，没有把上下行相加翻倍。结果含 CLI、C 服务端、TCP 及哈希核验开销，是完整本地路径的观测，不是密码算法的纯计算基准，也不代表真实 VPN 国密链路速度。兼容差异、负向校验及源码复现步骤见 [传输能力](transports.md)。
